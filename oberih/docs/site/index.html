Швидкий старт

Мова написана на Python, залежність одна — lark.

pip install -r requirements.txt
python3 oberih.py run examples/04_control_flow.obh

Щоб запустити файл із реальними мережевими викликами (не симуляцією), просто виконай oberih.py run без прапорця — справжня мережа увімкнена за замовчуванням. Для внутрішніх демонстрацій зі симульованими збоями додай --mock.

Головна ідея: Shared Budget

Найгірший клас збою в розподілених системах — retry storm: коли вкладені виклики з власними retry-політиками множаться, довершуючи падіння вже перевантаженого сервісу. Замість того, щоб кожна функція мала незалежний рахунок спроб, увесь ланцюжок викликів має єдиний бюджет часу і спроб, який передається вниз автоматично. 

resilient fn getOrderSummary(orderId: String) -> Result<OrderSummary, ResilienceExhausted>
    deadline(2s)
    retryBudget(6)
    fallback(cachedSummary(orderId))
{
    let order = fetchOrder(orderId)?
    let user = fetchUser(order.userId)?
    let payment = fetchPaymentStatus(order.id)?
    return Ok(OrderSummary(order, user, payment))
}

Вкладені виклики можуть оголошувати власний retries(n), але це стеля, обмежена залишком спільного бюджету — не додаткові спроби. Компілятор вимагає явний deadline і retryBudget на кожній кореневій resilient-функції. Без цього код просто не скомпілюється.

Основи мови

Поза модифікаторами стійкості Oberih — звичайна мова загального призначення: типи Number, String, Boolean, struct, List<T>, Map<K,V>, керуючі конструкції if/else, while, for, арифметика з правильним пріоритетом операцій, рекурсія з tail-call optimization. 

struct Point { x: Number, y: Number }

fn sumUpTo(n: Number) -> Number {
    let total = 0
    for (i in [1, 2, 3, 4, 5]) {
        total = total + i
    }
    return total
}

Проєкт можна розбити на кілька файлів через import "шлях/до/файлу.obh", а компілятор перевіряє типи до запуску - включно з полями структур і елементами списків.

П'ять пілонів

1. Shared Budget

Спільний бюджет часу/спроб, що запобігає retry storm - описано вище.

2. Durable Execution

durable вмикає журнал на диску: кожен вкладений resilient-виклик чекпоінтиться. Якщо процес реально впаде посеред виконання, повторний запуск з тими самими аргументами пропускає вже завершені кроки і довиконує лише те, що не встигло.

3. Узагальнений бюджет

budget(tokens: 50000) застосовує ту саму логіку Shared Budget не тільки до часу й спроб, а до будь-якого ресурсу - токенів LLM, грошей. Захищає від "AI-агент витратив тисячі доларів у retry-циклі".

4. Вбудована обсервабельність

traced на кореневому виклику автоматично генерує дерево спанів для всього ланцюжка вкладених викликів - без жодного рядка ручного інструментування коду.

5. AI-агент-нативні виклики

agent.call(prompt) автоматично вмикає durable і traced, а компілятор вимагає явний budget(...) - інакше код не скомпілюється.

Повний приклад: AI-агент з усіма пілонами

Чотири рядки коду активують усі п'ять пілонів одночасно:

resilient fn askAssistant(question: String) -> Result<String, Error>
    deadline(10s)
    retryBudget(3)
    budget(tokens: 2000)
{
    return agent.call(question)
}

durable і traced увімкнуться автоматично, бо тіло функції звертається до agent.call. Без budget(...) цей код взагалі не скомпілюється.

Чесні обмеження

  • Немає структур типу Result<T,E>/Option<T> як окремого типу даних - реалізовано через виключення.
  • bulkhead - варіант "reject if full", без черги очікування.
  • hedging не скасовує "програшну" паралельну спробу - вона довиконується у фоні.
  • Байткод VM покриває тільки прості функції без resilient-модифікаторів; вони й далі виконуються через повільніший tree-walking.
  • Немає LSP (автодоповнення, "go to definition") - тільки підсвітка синтаксису кольором.
  • Немає пакетного менеджера - import працює лише з локальними файлами.
